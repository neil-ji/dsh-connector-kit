安装

方式命令
npm（推荐）dsh plugin --profile <name> add dsh-connector-github
源码 / gitdsh plugin --profile <name> add github:neil-ji/dsh-connector-kit#<sha>
本地构建pnpm -r build && dsh plugin --profile <name> add file:./packages/dsh-github
git 安装时 pnpm ≥10 会拦截 build 脚本，需在 profile 的 pnpm-workspace.yaml 添加 allowBuilds 放行三个子包（dsh-connector-github / -ui / -wire）。
本地打包安装必须用 file: 前缀——默认 link: 不会安装 bundle 的子依赖。npm / tarball 安装（发布产物）无需 build 授权。

配置

全部配置在 Web 设置页（设置 → GitHub 连接）完成，持久化于 ~/.dsh/settings.yaml 的 github: 段：

项说明
tokenEnvcredential-ref，默认 GITHUB_TOKEN，值存 ~/.dsh/.credentials.yaml（只写不回读）
apiBaseGitHub API 地址，默认 https://api.github.com，可指向 GHES
gitName / gitEmail提交身份，留空用 git 全局配置
gitProxypush/pull 的代理（http/https/socks），如 http://127.0.0.1:7897，留空直连
defaultVisibility新建仓库默认可见性（private/public）
allow*九个权限闸门：CreateRepo / Push / Pull / PullRequest / Review / Pages / Actions / Issues / Release

推送 .github/workflows 文件需要 token 含 workflow scope（fine-grained PAT 需 Workflows 写入权限），设置页有提示。

npm 发布（7）

工具说明

token 需要 repo + workflow scope（classic PAT）才能覆盖全部工具的写操作。npm_* 工具需要同时安装 dsh-connector-github（复用 GitHub 凭证）。

npm 一键发布（SOP）

完整从零 SOP 见仓库 docs/SOP.md（含改名、2FA、OIDC 全部实测教训）。

1
npm_launch stage: launch

校验包名 → scaffold 可发布 TS 包（OIDC release 工作流 + Pages 站点）→ github_repo_create 建仓 → 推初始提交 → 开启 Pages

2
人工执行返回的 2FA 脚本（一次性）

首次 npm publish + npm trust 需要浏览器 2FA，Agent 无法代跑

3
npm_launch stage: tag

创建 v<next> annotated tag → CI 自动：对齐版本 → build → typecheck → test → OIDC 免 2FA 发布 → Pages

为什么不能全自动？ npm 2025-11 起禁 Classic/Automation token、2025-12 吊销存量；首次发布与 trust 是浏览器会话 2FA，绕不开。trust 配好后 CI 打 tag 即可零人工（OIDC trusted publishing）。

网络与代理

git push/pull 走 HTTPS + token；本机如遇 github.com 直连受限，配置 gitProxy 指向本地代理：

gitProxy: http://127.0.0.1:7897   # 设置页可配，留空直连（不覆盖用户全局 git 代理配置）

支持 http / https / socks 代理。设置页内置「测试代理」按钮（github/proxy.test），用 git ls-remote 验证与 push 完全相同的 HTTPS 路径。

SSH-over-443（ssh://git@ssh.github.com:443/<owner>/<repo>.git）可作为兜底出口，多数受限网络下比 HTTPS 代理更可靠。

发布流程（tag → npm → Pages）

  1. 提交代码到 main（pnpm typecheck && pnpm test && pnpm -r build 全绿）；
  2. 打 tag 并推送：git tag vX.Y.Z && git push origin vX.Y.Z；
  3. GitHub Actions release 工作流自动：对齐四包版本 → 构建 → 测试 → npm 发布（wire → ui → host → npm，OIDC trusted publishing）；
  4. 发布成功后构建本站（落地页 + 文档页，版本号自动注入）并部署到 GitHub Pages。

main 上 site/** 变更会触发 pages.yml 直接预览更新（不发布 npm）。

前置条件：四个 npm 包名已首次发布 + OIDC trust 已配置；仓库 Secrets 配置 NPM_TOKEN；Settings → Pages → Source 选择 GitHub Actions（否则 deploy-pages 失败）。

安全设计

token 隔离

token 只存在于 ctx.credentials 与请求头 / per-run 环境；Web 设置页只写不回读，值存 ~/.dsh/.credentials.yaml。

git 认证

内联 credential helper + per-run env：token 不进 argv、不进 remote URL、不进 .git/config。

危险操作零入口

不提供：删除仓库/分支/文件、force push、visibility 变更、webhook/secret 值写入。破坏性操作请在 GitHub Web/CLI 处理。

权限闸门

九个 allow* 开关（CreateRepo/Push/Pull/PullRequest/Review/Pages/Actions/Issues/Release）可在设置页逐项关闭。

架构

packages/
├── dsh-github/            # npm: dsh-connector-github（bundle + host 面插件）
│   ├── src/github-service.ts   # GitHubService: REST + git + 会话沙箱策略
│   ├── src/tools.ts            # 40 个 Agent 工具注册
│   └── cordis.patch.yml
├── dsh-github-ui/         # npm: dsh-connector-github-ui（client 设置页）
├── dsh-github-wire/       # npm: dsh-connector-wire（共享 wire 契约）
└── dsh-npm/               # npm: dsh-connector-npm（npm 一键发布 bundle）

npm 包名用 dsh-connector-* 系列（dsh-github 在 npm 已被占用）；运行时插件标识仍为 dsh-github / github-ui / npm，不影响已安装配置。wire 契约手写 strict Typert descriptors，host/client 两端共享同一份不漂移。

FAQ

为什么 npm 包名不是 dsh-github？

npm 上 dsh-github 已被占用（kazii 的另一项目）。本套件以 dsh-connector-* 系列发布（仓库 dsh-connector-kit）；运行时插件标识仍为 dsh-github / github-ui / npm，不影响已安装配置。

push 失败 / Connection reset？

多为网络问题：确认 gitProxy 可达（设置页「测试代理」），或换 SSH-over-443 兜底。

首次 npm 发布为什么必须人工？

npm 2025-11/12 收紧 2FA：无 automation token；首次 publish 与 trust 均为浏览器会话 2FA。trust 配好后 CI 打 tag 全自动（OIDC）。

npm trust 报 404？

trust 要求包已存在——顺序必须是先 publish 再 trust（POST /-/package/<name>/trust 404 = 包不存在）。

如何删除仓库 / 分支 / 文件？

插件刻意不提供任何破坏性操作，请在 GitHub Web / CLI 处理。
